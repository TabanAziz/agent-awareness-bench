# The gap

The claim I set out to defend: existing work measures whether the agent *succeeds over a long horizon*; nobody measures whether the agent *knows what is happening to it while it runs*. After the research phase, I believe that claim is right in spirit and too blunt in letter. Stated absolutely it is false in places: BAGEN elicits knowledge of mid-run state (offline, via prefix replay), and AgentCheck labels whether an agent detected an injected fault. The defensible version is narrower, and it is what this benchmark builds.

## What exists, sorted by what it actually scores

Reading [related-work.md](related-work.md), the works nearest my thesis fall into six families. Harness-variance studies and the sycophancy literature sit adjacent to all of them and inside none.

1. **Outcome evals** (Terminal-Bench, METR, SWE-bench line, Vending-Bench 1/2). Score the end state or a terminal dollar figure. Process quality appears only as post-hoc annotation (Terminal-Bench's own taxonomy) or retrospective audits of passing runs (AgentLens's lucky passes). They can tell me that an agent failed; not when it could have known.
2. **Offline elicitation** (BAGEN's prefix replay, MetaLoop's static tasks, KAPRO's pre-task calibration, Tools Fail's single-shot accept/reject judgments). Ask the model about its state under replay or in calm conditions. Whether awareness elicited that way predicts noticing mid-flight — with an ongoing task competing for the same context, stakes attached, and no question announcing that self-assessment is wanted — is not established anywhere I found. It is the first hypothesis this benchmark is built to test, not an axiom I assume.
3. **Vulnerability measurement** (Don't Blindly Trust It, EnvTrustBench). Inject bad evidence, score the damage. The dependent variable is the mistake, never the noticing.
4. **Detection handed over** (Outcome Monitors). An external detector finds the fault and hands the agent a receipt; the benchmark scores what happens next. Valuable — it isolates the behavior-change half — but it removes exactly the half I care most about.
5. **Post-hoc labeling** (AgentCheck, incident write-ups). Real faults injected into real agents, then labeled detected/recovered/propagated/fabricated after the run. Diagnostic, not metric: I found no detection latency against a machine-checkable onset, no wasted-compute accounting, and no benign no-fault controls in its published scenario composition.
6. **Decision-point abstention and resource awareness** (AgentAbstain, EcoAgent-Bench, BATS, CaRT, CostBench, CAM-DF). Score whether the agent stops, escalates, or stays within budget at discrete choice points. The resource axis only; the environment stays honest.

## What nobody combines

No found work does all four of these at once:

1. A fault whose onset is a **machine-checkable event** (`t_DP`) in a logged trace, detectable only from evidence the agent already received. The failure class of interest announces itself through neither exceptions nor exit codes — that is a selection criterion for what gets probed, not a claim that real failures never crash.
2. **Detection latency** per run against `t_DP`, where detection means an explicit verbalization of the actual problem in the agent's own transcript — the precise rubric lands in metrics.md — with non-detection reported as a rate rather than imputed.
3. A **clean-control false-alarm baseline**: identical runs with no fault, so awareness can be separated from paranoia. Wasted compute between `t_DP` and detection, normalized against control cost, follows mostly from latency but makes the cost concrete.
4. A **deterministic, harness-observed predicate** for behavior change after that independently defined detection event — the say-do gap — never the final answer, never a judge's impression of it.

Two further properties are hygiene rather than differentiation, listed so they are not mistaken for the novelty. Contamination resistance through procedural variants, because public benchmarks leak: OpenAI found models reproducing gold patches during its SWE-bench Verified audit ([why we stopped evaluating on it](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/)), and Cursor found 63% of successful Opus 4.8 Max resolutions on SWE-bench Pro retrieved the known fix rather than deriving it ([their audit](https://cursor.com/blog/reward-hacking-coding-benchmarks)). And the no-error-signal rule above. Each item alone exists somewhere; the combination — inline evidence-only detection plus latency plus false alarms plus a deterministic action gap — is empty in everything I read as of August 2026.

## Why the nearest teams have not shipped it

The obvious objection: AgentCheck plus Outcome Monitors' behavior scoring plus Tools Fail's calibration template, with timestamps and token meters bolted on, approximates items 1–4, and any of those teams could build it. True, and worth saying plainly: my claim is synthesis plus instrumentation, and the instrumentation is the moat. Latency against `t_DP` requires a harness-level event log where the fault onset is recorded alongside everything the agent was told — which requires owning every tool the agent touches. Clean-control false-alarm rates require generating matched faulty/control pairs from the same seed. Deterministic behavior predicates require observing actions the way the harness observes them, not annotating traces afterward. Of the three neighbors, Outcome Monitors is the most credible shipper: it already owns a live harness and detects faults inline, so for it the experiment is removing the external detector and adding meters, not building from scratch — and AgentCheck sits at the interception point too, since injecting timeouts already means controlling timing. What neither has, and what is genuinely hard to bolt on, is the evidence-only fault redesign and the deterministic say-do predicate; their pipelines were built to label damage or assist after detection, not to score noticing against a logged onset. If any of them ships exactly this, the falsification clause below applies to them first.

One lineage concession: time-to-detection and waste-against-baseline are staples of reliability engineering. The claim is domain transfer onto agent runtimes with a new dependent variable — the agent's own noticing — not metric invention.

## What would falsify this

If someone points me at a published benchmark that injects silent runtime faults, computes detection latency and wasted compute against a machine-checkable onset from the agent's own evidence stream, measures false alarms on clean controls, and scores behavior change deterministically after detection — then this page gets rewritten and the thesis narrows again. That is the honest failure mode, and I would rather find it now than get told in a review. Until then, the burden this repo carries is to make the four properties above true simultaneously and to keep them honest — including validating every detection predicate against a deliberately oblivious policy, which must score near zero on both detection and correct action if the probe measures anything real.
